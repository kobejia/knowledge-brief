# 知识简报

每次调用聚焦一个具体问题。使用宿主现有的阅读、检索和文件工具，结合三类输入完成“读历史、查资料、定主题、写简报、更新清单”。

## 读取配置与本次需求

读取用户指定或当前项目已明确绑定的配置文件；未指定时查找项目根目录的 `knowledge-brief.config.json`，存在多个候选且无法确定时才询问。配置样例见 [assets/config.example.json](assets/config.example.json)，只包含六项：

- `keywords`：非空关键词数组，提供长期探索范围。
- `description`：探索说明和关注点，可留空。
- `style`：语言风格。
- `source`：来源要求，可包含偏好网站或链接。
- `output_dir`：输出根目录，默认 `./src`。
- `template`：Markdown 模板路径，默认 `./brief-template.md`。

相对路径以配置文件所在目录为基准。本次调用的提示词决定本次重点、问题、角度或深度；未提供时按配置继续探索，不自动写回配置。

用户明确要求首次配置时，根据其提供的关键词创建上述六项配置，未指定的风格和来源使用样例默认说明；默认模板从 [references/brief-template.md](references/brief-template.md) 复制到配置旁，不覆盖已有文件。生成时配置或指定模板缺失、无效，应说明并请求提供或委托创建，不静默改用其他配置，不编造用户关键词。

## 读取历史并查询资料

1. 读取 `<output_dir>/list.json`。它是历史简报清单，结构见下节。读完全部日期、主题和摘要，数量较多时分批读取；通过条目的 `output_dir` 定位相近主题的 `brief.md`，需要时阅读原文、来源及图片。
2. 首次运行且根目录不存在或没有简报时，可创建根目录和空数组清单。已有简报但缺少清单时，先核对原文并补齐历史；清单损坏、无法读取，或指向的原文缺失时报告问题，不清空、不当成零历史继续。
3. 从配置关键词与说明、本次提示词和历史出发主动探索。阅读中追踪值得深挖的新概念、不同结论、跨来源联系和被忽略的问题；发现更有价值的切口时，可以调整问题、检索词和选题，保持与用户目标相关。探索应带来新的理解、判断或发现，不停在关键词解释或材料的机械汇总。按 `source` 查询并实际打开阅读资料，关键结论追溯原始研究、官方资料或可信的一手材料。
4. 对照历史的问题、机制、核心结论与适用条件判断新增价值。只换标题、措辞、例子或转载来源不算新内容；同一来源可以支持不同问题。重访旧主题必须增加新的判断方法、问题或证据，正文链接旧文并说明差异。
5. 资料可靠且有实质新增后确定主题，默认由 Skill 自行完成；本次提示词要求先看选题时，先交付候选并等待。资料不足时换题或补充查询，新进展不足时可以选未覆盖的经典知识并标注；没有合格题目时说明原因，不凑数。

## 生成与保存

读取配置 `template`，将其作为写作框架，按主题自主决定结构、小标题、详略和表达方式，以 `style` 控制语言。开篇尽快给出本次最值得知道的发现或回答；主体围绕它展开。例子、类比、操作建议和练习只在帮助理解时使用，实践主题可以直接讲清真实方法、流程与取舍，不必另造一个演示任务。

保持关键主张有实际阅读的来源支撑，区分事实、作者观点、推断与未知。只把会改变读者理解或选择的重要前提、代价、争议和不确定性放到相关结论旁边，不要求独立的“证据与边界”栏目，也不重复堆放通用免责声明。数字带关键条件，未知日期标未知；使用未运行的例子时在相应位置标“示意”。

涉及流程、分支、逻辑关系或交互时使用 Mermaid 图表，方法比较用表格；图文一致、箭头含义明确。需要外部图片时保存到当前主题的 `images/`，正文使用相对链接。阅读端不支持 Mermaid 时用可用工具渲染图片并保存图表源文件；显示无法确认时在交付说明中指出，工具探测和渲染诊断不写入知识正文。

为本篇选择具体的英文主题目录名，使用小写单词与连字符，如 `confidence-interval-coverage`。保存结构为：

```text
<output_dir>/
├── list.json
└── confidence-interval-coverage/
    ├── brief.md
    └── images/                      # 有图片时创建，含图片和图表源文件
```

每次调用可以生成一篇，同日也可生成不同主题。已有目录与文件不覆盖，新简报选择不同且具体的英文目录名；仅在用户明确要求替换时修改已有内容。日期使用用户当前时区，本项目为北京时间，格式 `YYYY-MM-DD`。

## 更新历史清单与交付

`list.json` 是 JSON 数组，每篇只含四项，`output_dir` 相对清单所在目录，指向该目录下固定的 `brief.md`：

```json
[
  {
    "date": "2026-11-06",
    "topic": "95% 置信区间如何理解？",
    "summary": "解释置信区间的覆盖率含义，区分方法的长期表现与单个区间的解读。",
    "output_dir": "confidence-interval-coverage"
  }
]
```

`summary` 用 1–2 句话概括正文的核心认识或方法，不能只复述标题。目录必须位于输出根目录内，不使用绝对路径或 `..`。

先保存正文和图片，再重新读取当前清单，保留已有条目并追加本篇；同一输出目录不重复追加。用户明确替换旧篇时更新对应条目。保存后回读检查 JSON 可解析、条目仍为四项、目录与 `brief.md` 存在、摘要与正文一致、本地图片和旧文链接有效，然后返回简报和清单的绝对文件链接。内容已保存但清单更新失败时，说明已保存位置和未同步状态，不声称全部完成。

查询历史时先检索清单，再按需读原文。用户反馈用于本次或后续明确的调用需求，长期偏好仅在用户要求修改配置时写入。每日触发由宿主调度，本 Skill 负责一次生成；历史比较和保存核验由 Agent 执行，不声称具备机械的语义去重或并发事务保证。
