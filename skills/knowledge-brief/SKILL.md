# 知识简报

每次聚焦一个问题，让读者新增一种解释、操作或判断能力。探索主题完全来自用户配置。用当前宿主的检索与阅读工具，不依赖其他方案文档，也不自动创建调度任务。

## 配置与初始化

只接受六项用户配置：`keywords`、`description`、`style`、`source`、`output_dir`、`template`。关键词为非空字符串数组，其余为字符串。样例在 [assets/config.example.json](assets/config.example.json)。

- 首次只需用户提供关键词；说明可留空，其余由初始化补默认值。不要替用户编造学习领域或背景。
- 用户要配置时，把输入写成 JSON，再执行 `node <skill-dir>/scripts/brief-store.mjs init --config <配置文件绝对路径>`。它补齐六项、建立输出目录并提供默认模板，保留已有模板。
- 日常使用已经指定或绑定的配置。多个配置无法确定时才询问选择；配置文件和模板的相对路径均以配置文件目录为基准。
- 修改配置必须来自用户明确请求。多个配置共用输出目录，就共用历史和每天一篇的约束。迁移同一份简报的输出目录时，连同完整历史迁移；不能换个空目录就声称去重继续有效。

脚本要求 Node.js 22 或更高版本。执行前阅读 [references/store-contract.md](references/store-contract.md)，获取命令、返回状态和草稿记录格式。所有路径参数用宿主 shell 的正确引用方式传递，不把 JSON 拼成 shell 命令。

## 生成今天的简报

1. 执行 `begin --config <路径>`。日期固定按北京时间、以启动时间为准。`reused` 就打开并返回已有简报；`busy` 表示同目录已有生成任务，不再另起一轮；`ready` 才开始生成。保存返回的 `run_id`、草稿位置、历史数量和摘要标识。
2. 读取当次运行快照中的配置和模板。分批执行 `history`，读完**全部历史索引**，再读最相近简报的全文及相关反馈。不能仅查看最近几天；不能读全历史时执行 `fail` 停止本轮。
3. 围绕关键词和说明找有缺口的问题。新进展优先最近 72 小时，必要时扩大到一周；没有合格新材料时选未覆盖的经典问题，明确标注“经典知识”。一次最多评估 5 个候选，不无限搜索。
4. 实际打开并阅读资料，遵循 `source`。技术主题优先论文、官方文档、作者代码与实验；其他领域优先原始研究、权威数据和一手材料。媒体可发现线索。官方宣传不等于效果证据，性能数字须带任务、对照及条件。
5. 选题先写出学习问题、学习成果、与最相近历史的增量。对照所有历史中的问题、机制、结论、证据、适用条件判断是否重复。只换标题、表达、例子或转载链接应拒绝。重访主题须有新问题、新判断方法，或改变旧认识的新证据，关联旧简报并说明差异。同一来源可支持不同问题，不因 URL 相同就淘汰。
6. 按快照模板写正文；以 `style` 控制表达。必须讲清问题、机制、证据、边界。通常 2–4 条实际阅读来源，不凑数量。区分事实、观点、推断和未知；未运行的例子标“示意”。涉及逻辑、流程、分支或交互时用图表，方法比较用表格；核对图文一致性和显示效果。阅读器不支持 Mermaid 时，用可用工具转图片并归档源文件。不把缺少本地渲染工具等同于阅读器不支持；显示效果无法确认时，在交付状态中如实说明，不宣称已验证。工具探测、渲染诊断等运行信息不写进知识正文。
7. 在返回的草稿目录写 `brief.md`、`record.json` 和必要的本地图表文件，按契约填写全部历史比较依据、来源及候选取舍摘要。脚本只验证结构与确定性重复，不能替代真实阅读与语义判断。
8. 执行 `publish --config <路径> --run-id <本轮标识>`。只在 `succeeded` 或 `reused` 后返回全文和绝对归档链接。若返回发布后警告，先保留已发布结果，再按提示修复，不重复生成。

对无法核实的来源、无法确认的新意、模板与证据要求冲突、存储异常，执行 `fail` 并报告原因。选题全部被拒绝时，先在草稿 `record.json` 中保存 `candidate_reviews`，再结束本轮，便于复核取舍。只有记录确认保存后才称“已留痕”；错误输出 `persisted: false` 时说明记录未落盘。

## 历史与反馈

- 查询历史：执行 `history`，按请求汇总日期、问题、结论和全文链接。历史多时分页读取。已生成不等于已掌握。
- 记录反馈：执行 `feedback --config <路径> --brief-id <日期> --text <原始反馈>`；明确关联哪篇，不能猜测目标。不改写旧简报。
- 生成中断：保留运行标识。锁没有自动过期，不按时间强行抢占。只有确认原调用已结束时，才用 `fail` 结束该运行；如果已完整发布，脚本会恢复为成功并重建索引。无法确认原调用是否结束时，报告正在生成，交给调用方处理。

## 能力边界

脚本保证同一输出目录同一天最多一篇，并校验归档与历史完整性；语义新颖性依赖模型对真实历史的判断，不能承诺永久零误判。无合格题目时保留失败记录，不生成占位简报。

每日自动运行由外部调度器调用本 Skill。启用前必须实际验证宿主可加载 Skill、联网、读取同一持久历史、显示结果；自动任务使用配置文件绝对路径。手动测试通过不等于定时触发已验证。
